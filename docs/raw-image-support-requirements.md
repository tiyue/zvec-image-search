# Sony A7M4 ARW 选片模块需求规格

状态：需求已确认，尚未实施
确认日期：2026-08-03
目标平台：Zvec-Webview Windows 源码版

## 1. 目标

新增一个独立的 Windows「ARW 选片」模块，用于项目化导入、快速浏览、双图对比、星级/色标筛选、统一导出和批量永久删除摄影文件。

本模块追求类似专业选片工具的体验：导入操作只登记源文件引用，首屏缩略图按最高优先级渐进生成；不得等待全项目缩略图或完整 RAW 解码后才进入工作区。

本模块不参与现有图库索引、向量生成、搜索、推荐、偏好、曝光或模型调用。

## 2. 已确认的产品边界

### 2.1 支持的文件

- 普通图片：`.jpg`、`.jpeg`、`.png`，扩展名不区分大小写。
- RAW：只支持 Sony A7M4（ILCE-7M4）实际产生的 `.arw`。
- A7M4 的压缩、无损压缩各尺寸档及未压缩 ARW 均必须由真实样本验证；不得只用单一 ARW 样本宣称支持全部类型。
- 不支持其他相机 RAW 格式；遇到 CR2、CR3、NEF、RAF、DNG 等必须跳过并给出安全计数，不得交给通用图片解码器猜测处理。
- ARW 与同目录同名 JPG/PNG 是不同图片，不自动配对、合并或按内容去重。
- 同一规范化绝对路径在同一项目中重复导入必须幂等跳过；不同项目可以引用同一源文件。

### 2.2 平台与系统隔离

- 仅修改 Windows WebView 源码版的独立模块。
- Android 完全不参与：不得修改 Android 代码、UI、测试、网络并发或本地状态。
- LAN v1 完全不参与：不得新增 ARW/项目/缩略图路由，不得改变现有 LAN 响应。
- 不把文件加入现有 Zvec Collection、图库状态库或推荐数据库。
- 不调用嵌入、标注、搜索、推荐或其他模型。
- 不处理 XMP sidecar，不写回 ARW/JPG/PNG 元数据，不应用 Lightroom 调色；Sony 创意外观仅按第 7.4 节作用于本模块的派生预览。
- 不提供修图、裁切、构图、液化、污点修复、智能消除或联机拍摄。
- 不改变 GitHub Release 发布矩阵。

### 2.3 源文件原则

- 导入只引用源文件，不把原图复制到项目存储。
- 项目持久化不代表托管原图；源文件被外部移动或删除后，项目必须显示“源文件丢失”。
- 普通浏览、评级、色标、筛选、清缓存、移出项目和删除项目不得修改源文件。
- 只有用户显式执行“永久删除源文件”时才允许删除物理文件。

## 3. 项目管理与导入

### 3.1 项目页

- 左侧导航新增「ARW 选片」入口。
- 首屏为独立项目页，项目卡片显示：项目名称、缩略图拼图、图片数、更新时间。
- “新建项目”打开小型模态，只要求项目名称；名称去除首尾空白后必须为 1～40 个字符。
- 项目卡片支持进入、重命名、清除缓存和删除项目。
- 删除项目只删除项目成员关系、评级/色标、界面状态和派生缓存，永远不删除源文件。

### 3.2 空项目页

仅提供两个入口：

- 导入图片。
- 导入文件夹。

不得提供“进入联机拍摄”或其他相机控制入口。

### 3.3 文件夹导入

- 递归扫描所有普通子目录。
- 必须跳过目录 reparse point、符号链接和会造成递归环的入口。
- 只登记明确支持的扩展名。
- 默认按规范化文件名稳定排序；拍摄时间在后台读取完成后可作为另一个显式排序选项，但不得静默重排当前视图。
- 路径枚举和项目登记不得读取完整文件、计算 SHA-256 或执行完整 RAW 解码。
- 使用批量事务持久化；不得每发现一个文件就同步提交一次数据库。
- 首批路径可用后立即进入工作区并调度首屏缩略图，不等待整个目录扫描完成。
- 导入状态必须区分“引用已登记”和“缩略图已完成”，例如显示“已导入 1000 张，缩略图 126/1000”；不得把占位块出现描述为缩略图完成。

## 4. 选片工作区

### 4.1 布局

- 中央为单张大图预览。
- 底部为横向虚拟化缩略图胶片栏。
- 工具区提供：适合窗口、100%、Sony 创意外观、星级、色标、筛选、双图对比、统一导出、移出项目、永久删除源文件。
- 显示当前图片序号、明确选择数量、当前筛选数量和项目总数。
- 项目重新打开后恢复最近查看图片、各图片已选创意外观、筛选、排序和胶片栏滚动位置。
- 必须支持跟随系统的 light/dark mode，并在现有受支持最小窗口内保持可用。

### 4.2 前端视觉与交互一致性

- 本模块必须嵌入现有 Zvec-Webview 应用 shell 和左侧导航，不得另起独立皮肤、标题栏、导航体系或与现有页面割裂的全屏应用框架。
- 必须复用现有前端的设计 token 和既有组件行为，包括字体、字号、颜色、surface、间距、圆角、图标、按钮、输入框、下拉菜单、模态、危险操作、焦点环、hover、active、disabled 和 loading 状态。
- 用户提供的参考截图只用于说明项目页、导入、单图预览、胶片栏和双图对比的功能结构，不是视觉稿；不得照搬参考软件的配色、品牌元素、控件皮肤或布局尺寸。
- 本模块新增样式必须限制在模块作用域内；不得为了本模块改写现有全局 CSS、根级 token 或无关共享组件样式，不得引起现有图库、搜索、推荐或设置页面的视觉变化。
- 新增导航项、页面标题、工具栏、菜单和模态必须与现有同类页面保持相同的信息密度、对齐、层级和交互动效；不得加入纯装饰元素、蓝紫渐变、卡片套卡片或异常醒目的大标题/大按钮。
- light/dark 均跟随现有主题切换机制，不得维护第二套主题状态；在宽屏和现有受支持最小窗口下，工具栏允许按现有模式折叠或换行，但核心操作不得溢出、遮挡图片或变成不可达。
- 所有弹出菜单、选择器和普通模态必须支持点击外部及 `Escape` 收起，并正确恢复焦点；永久删除确认继续遵守第 11.2 节的危险操作规则。
- 实施验收必须把本模块与现有核心页面放在同一版本、同一 light/dark 和同一窗口宽度下做并列截图检查；不得只对本模块孤立截图后宣称风格一致。

### 4.3 缩放和平移

- `Ctrl + 鼠标滚轮`以鼠标所在图像位置为中心缩放。
- 普通鼠标滚轮滚动胶片栏或页面，不缩放大图。
- 右键按下并拖动用于平移放大后的图片；拖动期间阻止浏览器原生右键菜单。
- 双击预览在“适合窗口”和 100% 之间切换。
- 提供可点击的“适合”和“100%”按钮，不得只依赖隐藏手势。
- 切换图片时默认回到适合窗口，不能继承上一张超出边界的平移位置。
- 后台高质量结果完成后原位替换，不闪回占位、不改变当前缩放中心或平移位置。

### 4.4 虚拟化

- 项目包含 1000 张图片时，不得创建 1000 个同时活动的 `<img>` 或完整卡片节点。
- 网格/胶片栏只渲染当前视口和前后约两行/两屏 overscan。
- 前端与 Python/本地 HTTP 层按批次交换资产与状态，不得为每张图片进行一次同步 Python↔JavaScript 往返。
- 内存只保留当前图片、对比图片、相邻预览和当前可见缩略图；磁盘缓存与内存缓存分离。

## 5. 星级、色标、筛选与排序

### 5.1 星级和色标

- 星级为 0～5 星；`0`清除星级，`1`～`5`设置对应星级。
- 色标为：无、红、黄、绿、蓝、紫。
- 星级和色标只写入本模块独立数据库，不写回图片或 XMP。
- 星级和色标按“项目成员”保存；同一源文件在不同项目中的评级不自动同步。
- 单图工作区和双图对比页都必须能直接修改星级和色标。

### 5.2 筛选

- 支持星级精确筛选及“至少 N 星”。
- 支持一个或多个色标。
- 支持文件名包含。
- 支持已评级/未评级。
- 同一类别内多个选择取“或”，不同类别之间取“且”。
- 筛选变化后立即更新结果数量和胶片栏，不重新解码已经缓存的图片。
- 提供明确的“清除筛选”。

### 5.3 排序

支持以下稳定排序：

- 文件名。
- 导入顺序。
- 拍摄时间（元数据读取完成后可用）。
- 星级。

排序不得改变星级、色标、当前明确选择或源文件。

## 6. 双图对比

- 首版只支持两张图片，不做三图、四宫格或更多图片对比。
- 用户必须明确选择两张图片后才能进入对比；选择不足或超过两张时按钮禁用并给出简短说明。
- 对比页左右并排显示两张图片。
- 默认同步缩放和同步平移，并提供关闭同步的显式开关。
- `Ctrl + 鼠标滚轮`以鼠标所在一侧为缩放基准；右键拖动平移。
- 两侧均可设置星级和色标。
- 两侧均可独立选择 Sony 创意外观；切换一侧不得重解码、改色或替换另一侧，是否同步缩放不影响外观选择。
- `Esc`或返回按钮退出对比，恢复进入前的当前图片、选择和胶片栏位置。
- 对比页先显示两张足够清晰的快速预览；不得等待两张完整 RAW 都解码完成才提交页面。
- 高质量结果分别完成后分别原位替换，任一侧失败不得清空另一侧。

## 7. 解码与渐进预览

### 7.1 技术基线

建议使用：

- LibRaw：ARW 容器、内嵌预览和完整 RAW 解码。
- rawpy 或等价的受控 LibRaw 绑定：Python 接线。
- 经许可、可复现并通过真实 A7M4 参考结果校准的色彩渲染层：只负责第 7.4 节的 Sony 创意外观；LibRaw 默认处理不能替代该层。
- Pillow/libjpeg-turbo：方向归一化、JPG/PNG 解码、缩放和 JPEG 缓存编码。
- SQLite：独立项目与操作状态。
- Vue 3 + Canvas 2D 或等价无额外重型依赖的显示层：缩放、平移和双图对比。

实现前必须验证最终 Windows 打包 Python 运行时具有受支持、可复现的 rawpy/LibRaw 构建；锁定版本和哈希，并审查 rawpy/LibRaw 的许可证及供应链。不得只在开发机临时安装未锁定依赖。

### 7.2 三级加载

1. **缩略图**：优先从 ARW 内嵌 JPEG 生成最长边约 384px 的持久化缩略图。
2. **快速大预览**：`拍摄时（As Shot）`优先使用足够清晰的内嵌预览，以保留相机拍摄时已经烘焙到内嵌 JPEG 的创意外观。
3. **完整解码**：内嵌预览不足、用户放大超过其有效分辨率，或用户切换到其他创意外观时，后台完整解码并按第 7.4 节渲染后原位替换。

“足够清晰”的最低判断为：内嵌预览宽高均不少于当前实际显示宽高的 1.25 倍。实现可以增加上限和设备像素比校正，但不得把明显低分辨率预览无限放大冒充完整结果。

### 7.3 完整 ARW 解码

- 使用相机白平衡。
- 创意外观应用前使用受控的高位深中间结果，最终派生预览输出标准 sRGB、正确方向的 8-bit 图像；不得先量化为低精度图像再反复套用外观。
- 不读取或应用 XMP、Lightroom 调色或用户未要求的自动增强；Sony 创意外观只能通过第 7.4 节定义的显式路径应用。
- 完整解码失败时保留已经可用的内嵌预览并显示安全错误；不能使项目或主程序退出。
- 损坏、截断、不受支持变体和解码超时必须按单文件失败处理。

### 7.4 Sony 创意外观

#### 7.4.1 产品行为

- 每张 ARW 首次导入后的默认选择为 `拍摄时（As Shot）`。快速预览优先显示 ARW 内嵌 JPEG，以保留拍摄时相机实际应用的创意外观及其自定义参数；不得默认显示未经外观处理的灰平或通用 LibRaw 结果。
- 若能从 A7M4 MakerNote 或其他受验证元数据中可靠识别拍摄时外观，UI 可以在 `拍摄时`旁显示已验证的外观名称；无法可靠识别时只显示 `拍摄时`，不得根据画面或不完整字段猜测名称。
- ARW 必须能够切换 A7M4 提供的全部原厂预置创意外观。实施前必须以 Sony 官方 A7M4 当前帮助指南和真实相机/固件核对最终集合；预期核对基线为 `ST`、`PT`、`NT`、`VV`、`VV2`、`FL`、`IN`、`SH`、`BW`、`SE`，不得仅凭这份预期列表跳过官方及实机核验。
- 首版只提供 `拍摄时`和经核验的原厂预置切换，不新增对比度、亮部、阴影、褪色、饱和度、锐度、锐度范围或清晰度等手工细调控件。拍摄时的相机自定义参数仍由内嵌 JPEG 如实呈现。
- JPG/JPEG/PNG 的像素已经定稿，不执行二次 Sony 创意外观渲染；这些文件显示原始图像，创意外观选择器必须禁用或明确标记为不适用。
- 用户为某张 ARW 选择的外观按“项目成员”持久化，初始值始终为 `拍摄时`；同一源文件在不同项目中的外观选择互不联动，重启应用、重新打开项目或清除派生缓存后仍保留选择。
- 创意外观只影响本模块的缩略图和预览派生结果，不修改 ARW、MakerNote、XMP 或任何源文件。第 10 节统一导出始终复制源文件原始字节，不烘焙当前外观，也不新增“导出带外观 JPEG”。

#### 7.4.2 色彩真实性与实现门禁

- LibRaw/rawpy 只作为 RAW 数据解码基础，不得把其默认色彩处理、名称相同的通用 LUT 或主观滤镜直接宣称为 Sony 原厂创意外观。
- 编码前必须核对是否存在允许随 Zvec Windows 包分发和自动调用的 Sony 官方渲染能力；若采用经真实样本校准的兼容配置，则必须锁定相机型号、固件范围、解码器版本、色彩配置版本及许可证，并明确记录其与官方渲染的适用边界。
- 每个预置必须使用同一批真实 A7M4 ARW，并以 Sony 官方软件输出或相机生成的可信参考 JPEG 做逐项校准；测试集至少覆盖日光、混合光、高反差、肤色、高饱和色和黑白场景，并同时记录客观色差/图像差异和人工视觉检查结果。
- `拍摄时`从内嵌预览切换到完整解码结果时不得出现可感知的白平衡、色调、饱和度或明暗风格跳变。完整解码无法可靠复现拍摄时外观时，应继续保留足够清晰的内嵌预览并明确报告高倍率限制，不得用不匹配结果静默替换。
- 若最终环境无法获得合法、可复现且通过真实参考校准的 Sony 创意外观渲染路径，该能力视为实施阻断；必须向用户报告证据和确切限制，不得交付伪“原厂”效果、占位预置或仅更换名称的滤镜。

#### 7.4.3 渐进加载与缓存

- 显示当前 ARW 的合格内嵌预览后，应按第 8.1 节高优先级在后台准备当前图片的基础完整解码；不得在导入阶段为 300～1000 张图片完整解码，也不得预渲染每张图片的所有创意外观。
- 切换外观时保留当前可用画面，新的低分辨率/当前视口结果和高质量结果依次原位替换；不得清空预览、跳回占位或改变缩放中心和平移位置。
- 当前单图或双图对比中的基础解码结果可以复用，不同外观不得重复执行相同的 RAW 解包、去马赛克和基础颜色转换；切图、离开项目或取消后使用 generation/token 阻止迟到外观覆盖当前图片。
- 派生缓存键除第 8.4 节的源版本字段外，必须包含外观 ID、外观配置版本、解码/颜色管线版本、输出尺寸和色彩空间；任何外观配置或管线版本变化都必须失效旧结果。
- “清除项目缓存”删除所有外观派生结果和可重建的基础解码缓存，但保留每个项目成员已选择的外观；再次查看时按需重建。

### 7.5 JPG/PNG

- JPG 应使用支持缩放解码的高性能路径，避免为了 384px 缩略图总是完整展开高分辨率像素。
- PNG 保持透明度；预览背景跟随界面 surface，不改写源文件。
- EXIF 方向必须在缩略图和大预览中一致。

## 8. 调度、并发与缓存

### 8.1 任务优先级

固定优先级从高到低为：

1. 当前大图。
2. 双图对比的第二张图。
3. 当前视口可见缩略图。
4. 当前图片前后相邻预览及视口 overscan。
5. 项目剩余缩略图。

用户滚动、切图、进入对比或切换项目时，新的可见任务必须抢在尚未开始的低优先级任务之前。项目切换/关闭后取消未开始的旧任务，并使用 generation/token 防止迟到结果覆盖当前项目。

### 8.2 并发矩阵

必须用同一组真实只读输入、独立临时缓存分别测试：

| 任务 | 固定基准档位 |
| --- | --- |
| ARW 内嵌预览/缩略图 | 8 / 12 / 16 / 24 |
| JPG 缩略图 | 8 / 12 / 16 |
| PNG 缩略图 | 4 / 6 / 8 |
| ARW 完整解码 | 2 / 3 / 4 / 6 |

本模块以吞吐和首屏速度优先，不要求选择收益拐点处的最小值；生产采用满足内存、错误和 UI 响应硬门禁时吞吐最高的有界档位。禁止无界线程池、无界进程池或无界任务队列。

完整 RAW worker 必须避免“外层多进程 × LibRaw 内部多线程”的乘法超卖；必要时把每个 worker 的内部线程限制为 1。完整解码建议运行在可重启的隔离辅助进程中，防止原生解码器异常带崩 WebView 主进程。大像素数组不得经高成本 IPC 来回复制；worker 应原子写入缓存并只返回安全缓存标识和尺寸。

### 8.3 请求合并

- 同一文件同一版本、同一缓存规格的并发请求只允许实际解码一次。
- 等待者共享成功或失败结果；失败必须释放所有等待者并允许后续显式重试。
- 任务取消、项目删除或源版本变化后，旧结果不得重新写回有效缓存。

### 8.4 持久缓存

建议独立存放：

```text
raw-selection/
  projects.sqlite3
  cache/
    thumbnails/
    previews/
    full/
```

- 所有资产按需持久化 384px 缩略图。
- 大预览只为当前、相邻及进入过对比的图片按需生成并持久化；导入时不得预先保存 1000 张完整大预览。
- 完整解码缓存只在实际需要完整分辨率时生成。
- 缓存键至少包含规范化源路径、文件大小、`mtime_ns`、文件身份及解码版本。
- 缓存采用临时文件 + 原子替换；不得留下可被误读的半文件。
- 退出程序不删除磁盘缓存，不按时间自动清理磁盘缓存。
- 空间不足时停止创建新缓存并给出明确错误；不得自动删除其他项目缓存。
- “清除项目缓存”只删除派生缓存，保留项目引用、星级、色标和筛选状态；之后按需重新生成。
- 内存缓存可以使用有界 LRU，不等同于清除持久化项目。

## 9. 独立持久化模型

逻辑上至少需要：

- 项目。
- 规范化源资产及精确文件版本。
- 项目与资产的成员关系。
- 项目级星级和色标。
- 缓存版本与状态。
- 导入、导出和永久删除操作日志/恢复状态。
- 最近查看位置、筛选和排序状态。
- 每个项目成员已选择的 Sony 创意外观。

实际表名应匹配项目风格，但必须使用本模块独立 SQLite；不得复用或扩展推荐数据库，不得把这些引用写入现有 Collection 状态。

重新启动后必须恢复：项目、成员、星级、色标、每张 ARW 已选创意外观、筛选、排序、当前图片、胶片栏位置、缓存索引及未完成永久删除操作的安全收尾状态。

## 10. 统一导出

### 10.1 唯一导出语义

- 不提供“复制预览图”“复制原图”或其他图片/文件剪贴板操作。
- 统一使用“导出”按钮选择目标目录。
- ARW 按原始 ARW 字节导出；JPG/PNG 保持原格式和原始字节。
- 不提供 ARW 转 JPEG，不对导出内容进行重编码、调色或元数据改写。
- 支持导出当前图片、明确选中图片和“全选当前筛选结果”后形成的明确选择。
- 不允许一个危险/批量操作隐式作用于未明确选择的筛选结果；UI 必须先显示最终选择数量。

### 10.2 冲突与结果

- 不覆盖现有目标文件。
- 重名采用确定性序号后缀，保持扩展名。
- 批量导出保持稳定输入顺序并报告进度。
- 失败不撤销已经成功导出的文件；返回明确的成功/失败清单。
- 测试必须验证导出文件与源文件内容摘要完全一致。
- 用户取消目录选择时不创建任务、不产生输出。

## 11. 移出项目与永久删除源文件

### 11.1 两个完全独立的操作

**移出项目**：

- 支持单张和批量。
- 只删除当前项目成员关系及该项目不再需要的派生状态。
- 不修改源文件，不影响其他项目对同一源的引用。

**永久删除源文件**：

- 支持单张和批量。
- 使用精确文件删除，不进入 Windows 回收站，不可恢复。
- 成功后从所有项目移除该规范化源路径的所有引用、项目级评级/色标及全部派生缓存。
- 同一路径被多个项目引用时，物理文件只删除一次。
- 同名 ARW/JPG/PNG、同名 XMP 或其他 sidecar 不得连带删除；只有明确选择的精确文件可以成为目标。

### 11.2 永久删除确认

- “永久删除源文件”与“移出项目”使用不同按钮、不同文案和不同处理函数。
- 永久删除按钮使用现有设计系统的危险操作样式，不得成为默认焦点或默认回车操作。
- 确认框必须显示文件数量、总大小和“不会进入回收站、无法恢复”。
- 批量操作只作用于明确选中的文件；可以先“全选当前筛选结果”，但必须再次显示最终数量。
- 用户必须勾选“我理解这些源文件将被永久删除”后才能点击最终“永久删除”。
- 最终确认后不提供取消，避免制造用户误以为已经删除内容可以恢复的语义。

### 11.3 路径安全

- 删除目标只能来自数据库中已经登记的单个资产绝对路径。
- 禁止目录、通配符、递归删除、字符串拼接目标、符号链接、reparse point 或解析后身份发生改变的路径。
- 删除前重新核对规范化路径、文件类型、文件版本和可取得的 Windows 文件身份；与用户确认时的目标不一致则该项失败。
- 不提升权限，不修改 ACL，不清除只读属性；只读、正在使用或拒绝访问的文件保留并报告失败。
- 已经被外部删除的文件记为 `already_missing`，不再执行物理删除，并从所有项目清除失效引用。

### 11.4 批量永久删除的一致性与恢复

文件系统删除与 SQLite 不能形成一个原子事务，因此必须使用可恢复的两阶段操作日志：

1. 在执行前持久化精确目标清单、确认状态和源版本。
2. 逐项永久删除，记录每项结果。
3. 每个删除成功或已经缺失的源，从所有项目清除引用和缓存。
4. 删除失败项保留所有项目引用和评级，并报告安全原因。
5. 若进程在“文件已删除、数据库未清理”之间退出，下次启动根据操作日志完成引用清理。

不得为了表面上的全有或全无而尝试恢复已经永久删除的文件。批量结果必须区分：已删除、已缺失并清理、失败并保留。

## 12. 外部变化与错误状态

- 每次使用缓存前核对精确源版本；文件变化后失效旧缓存并重新生成。
- 源文件移动/删除后显示“源文件丢失”，除非有已确认的永久删除日志需要自动完成项目清理。
- 损坏图片显示单项错误占位，不能阻塞其他图片加载、筛选或评级。
- 项目切换、窗口关闭和进程退出必须安全停止/收尾任务，不留下运行线程、子进程、临时缓存或 SQLite 未提交事务。
- 错误信息不得包含 traceback；本地 UI 可以显示用户已导入文件的名称和路径，但日志/诊断导出必须遵循现有隐私约束。

## 13. 性能场景与硬门禁

### 13.1 固定目标环境

- 单项目 300～1000 张。
- A7M4 ARW 单张约 50～70MB。
- 源文件位于本机 SATA SSD。
- 参考输入必须覆盖目标 A7M4 的全部 ARW 类型，并包含 JPG/PNG 混合项目。

### 13.2 计时定义

- “工作区出现”：用户确认文件/文件夹选择到项目 UI 可操作、引用记录已经开始持久化。
- “前 24 张可见”：前 24 张真实缩略图已经成功解码、提交 DOM 并可见；占位块、缓存伪命中和同一文件重复项不计。
- “缓存重新打开”：关闭并重新启动源码版后，使用原持久化项目和缓存进入工作区。
- “缓存创意外观切换”：目标外观、源版本、输出尺寸和色彩管线版本完全命中有效派生缓存，从用户确认切换到新画面提交且可见。
- “未缓存创意外观切换”：目标外观派生结果不存在；必须分别注明基础完整解码是内存命中、磁盘命中还是也需重新解码，不得混合统计。
- 所有正式冷路径使用独立空派生缓存，禁止用第二次运行或相同缓存结果冒充冷导入。

### 13.3 门禁

在目标环境上必须达到：

- 确认文件夹到工作区可操作 P95 `<=300ms`。
- 冷缓存前 24 张真实缩略图全部可见 P95 `<=1s`。
- 冷缓存前 100 张缩略图完成 P95 `<=3s`。
- 1000 张后台缩略图全部完成 P95 `<=20s`。
- 已缓存项目重启后首屏 24 张可见 P95 `<=200ms`。
- 有合格内嵌大预览时，点击到大图可见 P95 `<=300ms`。
- 已缓存大预览切换 P95 `<=100ms`。
- `拍摄时（As Shot）`仍必须使用快速内嵌预览满足大图可见 P95 `<=300ms`，不得因后台准备创意外观而阻塞首屏。
- 缓存创意外观切换并提交可见 P95 `<=200ms`。
- 未缓存创意外观切换必须在 `<=100ms` 内反馈切换已开始并保留旧画面；使用真实 A7M4 样本分别报告各预置在基础解码内存命中、磁盘命中和冷解码三种口径下的 P50/P95，在建立真实基线前不伪造统一完成时限。
- 两张已缓存图片进入对比并提交 P95 `<=200ms`。
- 后台导入/缩略图期间，滚动、星级和色标操作响应 P95 `<=100ms`。
- 正式输入缩略图错误为 0；损坏/不支持的专门错误样本必须安全失败且不影响其他条目。
- 任务完成、取消、项目关闭或辅助进程重启后，线程、进程、队列等待者和临时缓存残留均为 0。

完整 RAW 解码必须报告每种 A7M4 ARW 类型在 2/3/4/6 路下的 P50/P95、吞吐、CPU、峰值内存和磁盘 I/O；在没有真实基线前不伪造固定解码时间目标。生产选择满足错误、内存和 UI 响应硬门禁时吞吐最高的档位。创意外观基准必须单独区分基础解码和外观渲染耗时，不能把后台提前解码时间排除后将结果描述为完整冷切换。

### 13.4 基准方法

- 至少使用 300 张真实只读 A7M4 ARW，覆盖全部目标模式。
- 各并发档使用相同顺序、相同输入和独立临时缓存。
- 首屏门禁至少执行 20 组真实冷缓存首 24 张，报告 P50/P95和错误数。
- 每个经核验的创意外观至少覆盖 20 组真实切换；使用相同样本顺序和隔离派生缓存，分别报告基础解码、外观渲染、编码/缓存和 UI 提交耗时，以及缓存命中率与取消数。
- 记录 CPU 平均/峰值、进程及辅助 worker 峰值内存、读写字节或可复跑等价 I/O 指标。
- 记录 UI 响应、取消/项目切换延迟、迟到结果和残留。
- 不关闭系统安全软件、不污染用户项目数据库和正式缓存、不修改源文件。

## 14. 必须补充的测试

### 14.1 导入与持久化

- ARW/JPG/JPEG/PNG 大小写扩展名。
- A7M4 全部 ARW 类型。
- 递归文件夹、空文件夹、不支持格式、reparse/symlink 环。
- 同路径同项目重复导入幂等；同名不同扩展名分别存在；不同项目共享源引用。
- 1000 张项目批量登记、渐进缩略图和重启恢复。
- 星级、色标、筛选、排序、当前图片和胶片位置重启后保持。
- 手动清缓存后源和评级不变，缩略图可正确重建。

### 14.2 解码和缓存

- ARW 内嵌 JPEG 提取、无合格预览时完整解码、正确方向和 sRGB。
- JPG EXIF 方向、PNG alpha。
- 损坏、截断、不支持 ARW 变体、超大输出和解码超时。
- 同图并发 single-flight、失败释放等待者、源变化失效、原子缓存写入、辅助进程崩溃后恢复。
- 高质量结果替换不改变缩放/平移，不让迟到结果覆盖新项目。

### 14.3 Sony 创意外观

- 新导入 ARW 默认 `拍摄时`，内嵌 JPEG 正确保留相机拍摄时外观；可可靠识别和不可识别 MakerNote 时均不猜测错误名称。
- 以官方文档和真实 A7M4/固件核对完整预置集合，并逐个验证选择、渲染、方向、白平衡和 sRGB 输出；不得只测一两个代表性预置。
- 使用 Sony 官方软件输出或相机生成的可信参考 JPEG，对日光、混合光、高反差、肤色、高饱和色和黑白样本做客观差异与人工视觉校准，并保存可复核结果。
- `拍摄时`内嵌预览升级到完整解码时无明显色彩跳变；无法可靠匹配时保留内嵌预览并暴露确切限制。
- JPG/JPEG/PNG 不二次应用创意外观，选择器禁用或明确显示不适用。
- 每张 ARW 的外观选择按项目成员持久化；不同项目互不联动，重启和清缓存不丢失。
- 缓存键包含外观及管线版本；切换外观配置、源文件版本或输出规格后旧结果严格失效。
- 单图快速连续切换、切图、切项目、取消和迟到结果；旧外观不得覆盖当前图片或当前选择。
- 双图两侧独立外观，任何一侧失败、取消或完成不得改变另一侧。
- 切换、缓存、重启、清缓存和统一导出前后核对源文件内容摘要与元数据均未改变；导出摘要始终与源一致。

### 14.4 UI

- Ctrl+滚轮以指针为中心缩放；普通滚轮不缩放大图。
- 右键拖动平移并抑制原生菜单。
- 双击适合/100%、按钮行为和切图复位。
- 1000 张虚拟化胶片栏不会创建全量节点。
- 星级、色标、组合筛选和稳定排序。
- 双图选择数量校验、同步/独立缩放平移、分别评级、Esc 返回和滚动位置恢复。
- 弹出式菜单/模态支持点击外部和 Escape 收起（永久删除确认按安全规则处理）。
- Windows light/dark、宽屏及现有受支持最小窗口视觉检查，保留真实截图。
- 与现有图库、搜索、推荐和设置页面做同主题、同窗口宽度并列截图回归，核对导航、字体、颜色、间距、圆角、按钮、菜单、模态、焦点和危险操作风格一致；现有页面不得因本模块新增样式发生变化。
- 参考截图只验证功能结构，不得出现参考软件品牌元素或与 Zvec 现有设计体系割裂的皮肤。

### 14.5 导出

- 当前、明确多选和全选筛选结果。
- ARW/JPG/PNG 输出摘要与源一致。
- 同名冲突、目标已有文件、缺失源、权限失败、部分成功、稳定顺序和进度。
- 用户取消目录选择不创建任务。

### 14.6 永久删除

删除测试只能使用显式创建并校验的临时副本目录，绝不能对用户真实样本执行：

- 移出项目不删除源。
- 单张/批量永久删除不进入回收站。
- 同一源被多个项目引用时只删一次并从所有项目移除。
- 同名 ARW/JPG/PNG/XMP 不连带删除。
- 目录、通配符、symlink、reparse point、路径替换和版本变化全部拒绝。
- 只读、占用、权限失败保留所有项目引用。
- 已缺失文件从所有项目清理并标记正确结果。
- 成功/失败混合清单、进程中断和两阶段日志恢复。
- 删除项目绝不删除源文件。
